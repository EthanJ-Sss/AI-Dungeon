## 📚 文档分类规则

### 1. docs/design/ - 设计文档

**存放内容**:
- 系统设计文档
- 功能设计方案
- 架构设计
- 数据结构设计
- UI/UX设计

**命名规范**:
- `[系统名称]-设计文档.md`
- `[功能名称]-设计方案.md`

**示例**:
```
docs/design/
├── 战斗系统设计文档.md
├── 技能系统设计方案.md
├── 火山关卡设计.md
└── 英雄系统架构设计.md
```

---

### 2. docs/development/ - 开发文档

**存放内容**:
- 开发计划
- 技术选型
- 开发进度
- API文档
- 待开发功能清单

**命名规范**:
- `开发计划.md`
- `[功能]-开发进度.md`
- `TodoList.md`

**示例**:
```
docs/development/
├── 开发计划.md
├── Sprint1-开发进度.md
├── TodoList.md
└── API文档.md
```

---

### 3. docs/completed/ - 已完成功能文档

**存放内容**:
- ✅ 标记的完成文档
- Sprint完成总结
- 功能实现总结
- Bug修复记录

**命名规范**:
- `✅[功能名称]-完成.md`
- `✅Sprint[N]-完成总结.md`
- `✅Bug修复-[问题描述].md`

**示例**:
```
docs/completed/
├── ✅Sprint1完成.md
├── ✅技能系统完成总结.md
├── ✅Bug修复-敌人消失问题.md
└── ✅关卡难度设计v3.0完成.md
```

---

### 4. docs/testing/ - 测试文档

**存放内容**:
- 🎯 标记的测试文档
- 测试指南
- 测试用例
- 问题复现步骤

**命名规范**:
- `🎯[功能]-测试指南.md`
- `🎯[系统]-测试用例.md`

**示例**:
```
docs/testing/
├── 🎯关卡系统测试指南.md
├── 🎯技能测试必看.md
├── 🎯BUFF系统测试指南.md
└── 🎯新关卡难度测试指南.md
```

---

### 5. docs/guides/ - 使用指南

**存放内容**:
- ⭐ 标记的启动文档
- 🎮 标记的操作指南
- 📖 用户手册
- 快速开始

**命名规范**:
- `⭐启动指南.md`
- `🎮[功能]-使用说明.md`
- `快速参考.md`

**示例**:
```
docs/guides/
├── ⭐启动游戏.md
├── 🎮战斗系统指南.md
├── 🎯关卡快速参考v3.0.md
└── 快速启动指南.md
```

---

### 6. docs/archive/ - 归档文档

**存放内容**:
- 过时的设计文档
- 已废弃的功能文档
- 旧版本文档
- 历史记录

**归档规则**:
- 当文档超过3个月未更新
- 功能已被重构或替换
- 保留但不再使用的设计

**命名规范**:
- 保持原名，但移到archive目录
- 可选：添加`[已归档]`前缀

## 📝 文件命名规范

### Emoji标识系统

| Emoji | 含义 | 使用场景 |
|-------|------|---------|
| ✅ | 已完成 | 功能完成文档、Bug修复完成 |
| 🎯 | 测试 | 测试指南、测试用例 |
| ⭐ | 重要 | 启动文档、核心指南 |
| 🎮 | 游戏 | 游戏相关指南 |
| 🎉 | 庆祝 | Sprint完成庆祝 |
| 🎊 | 里程碑 | 重大版本完成 |
| 🐛 | Bug | Bug相关文档 |
| 🔧 | 修复 | 修复工具、紧急修复 |
| 👉 | 指引 | 新手指引、下一步 |
| 📊 | 数据 | 数据分析、对比表 |
| 📋 | 规范 | 规范文档、清单 |

### 文件命名格式

**设计文档**:
```
[系统名称]-设计文档.md
[功能名称]-设计方案.md
```

**完成文档**:
```
✅[功能名称]-完成.md
✅[功能名称]-完成总结.md
✅Sprint[N]-完成.md
```

**测试文档**:
```
🎯[系统名称]-测试指南.md
🎯[功能名称]-测试.md
```

**Bug文档**:
```
✅Bug修复-[问题描述].md
🐛Bug记录-[问题描述].md
```

## 🔄 文档生命周期

### 1. 创建阶段

**新设计文档**:
```
docs/design/[功能名称]-设计.md
```

**新开发任务**:
```
docs/development/[功能名称]-开发进度.md
```

---

### 2. 开发阶段

**进度更新**:
- 在 `docs/development/` 下更新开发进度
- 在 `docs/testing/` 下创建测试文档

---

### 3. 完成阶段

**功能完成**:
1. 创建完成文档：`docs/completed/✅[功能名称]-完成.md`
2. 更新开发文档状态
3. 如果有测试文档，保留在 `docs/testing/`

---

### 4. 归档阶段

**何时归档**:
- 功能被重构或替换
- 文档超过3个月未更新
- 版本已过时

**归档方法**:
```bash
# 移动到归档目录
mv docs/design/旧功能设计.md docs/archive/
```

## 🚫 禁止事项

### ❌ 不要这样做

1. **不要在项目根目录堆积文档**
   - ❌ 错误：`/✅技能系统完成.md`
   - ✅ 正确：`/docs/completed/✅技能系统完成.md`

2. **不要在代码目录放文档**
   - ❌ 错误：`/astrocade/设计文档.md`
   - ✅ 正确：`/docs/design/设计文档.md`

3. **不要混淆不同类型的脚本**
   - ❌ 错误：部署和开发脚本混在一起
   - ✅ 正确：分别放在 `scripts/deploy/` 和 `scripts/dev/`

4. **不要使用无意义的文件名**
   - ❌ 错误：`doc1.md`, `test.md`, `新建文本文档.txt`
   - ✅ 正确：`关卡系统设计.md`, `技能测试指南.md`

## ✅ 最佳实践

### 1. 创建新文档时

**步骤**:
1. 确定文档类型（设计/开发/测试/指南）
2. 选择对应目录
3. 使用规范的命名
4. 添加适当的Emoji标识

**示例**:
```bash
# 创建设计文档
touch docs/design/装备系统设计.md

# 创建测试文档
touch docs/testing/🎯装备系统测试指南.md

# 功能完成后
touch docs/completed/✅装备系统完成.md
```

---

### 2. 定期整理

**每周检查**:
- [ ] 检查根目录是否有散落文档
- [ ] 将临时文档移到对应目录
- [ ] 删除不需要的临时文件

**每月归档**:
- [ ] 检查是否有过时文档需要归档
- [ ] 整理 `docs/archive/` 目录
- [ ] 清理重复文档

---

### 3. 版本控制

**文档版本号**:
- 重大修改：v1.0, v2.0, v3.0
- 小修改：v1.1, v1.2

**命名示例**:
```
✅关卡难度设计v3.0.md
🎯关卡快速参考v3.0.md
```

## 🎯 实施计划

### 第一阶段：整理现有文件

**使用自动整理工具** ⭐ 推荐:
```batch
# 双击运行
🔧一键整理项目目录.bat

# 或在命令行运行
.\scripts\maintenance\整理项目目录.bat
```

**手动整理**:
1. 将所有 `✅` 开头的文档移到 `docs/completed/`
2. 将所有 `🎯` 开头的文档移到 `docs/testing/`
3. 将所有 `⭐🎮` 开头的文档移到 `docs/guides/`
4. 将设计文档移到 `docs/design/`
5. 将脚本文件移到 `scripts/` 对应子目录

### 第二阶段：建立规范
1. 团队学习本规范文档
2. 在 `.cursor/rules/` 中添加目录规范
3. 设置文件模板

### 第三阶段：持续维护
1. 每次创建文档时遵循规范
2. 定期检查和整理
3. 及时归档过时文档
